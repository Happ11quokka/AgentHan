# 모델은 의미만, 진행은 코드로: HCX 지원 범위와 실측 (2026-11-12)

질문: HCX가 "기능 고르기 + 인자 채우기"만 하고, 되묻기·미리보기·승인·완료 문구·작업 전환은 코드(규칙)가 맡는 구조가 가능한가?

## 결론

1. **API는 된다.** HCX-005는 도구 강제 호출(`toolChoice`에 특정 함수 지정)을 받는다. 400 없이 40회 모두 호출이 돌아왔다(실측). 구조화 출력(`responseFormat`)은 HCX-007만 된다.
2. **짧고 깨끗한 문맥에서는 강제하지 않아도 HCX-005가 도구를 부른다.** 오늘 S1에서 말로만 처리하거나 되묻던 턴 3개를 시스템 한 줄 + 해당 대화만으로 다시 보내면, `auto`와 강제 모두 5/5 정확한 인자로 호출했다.
   → 오늘의 실패는 모델의 도구 호출 능력 때문이 아니라 **지금 넣어 주는 문맥(긴 시스템 프롬프트, 대화 기록, 시스템 문구)** 때문이라는 쪽에 무게가 실린다.
3. **남는 실패는 의미(인자) 오류이고, 강제 호출로도 안 고쳐진다.** "월요일은 10시~9시, 금요일은 11시~10시"를 `auto`·강제 모두 10/10 `days=[mon,fri] 10–21` + `days=[fri] 11–22`로 냈다. 월요일만 바꿔야 할 첫 호출에 금요일이 들어간다. 이건 스키마 문제다(요일 목록 + 시간 하나 → 요일별 항목 배열로 바꾸면 모델이 틀릴 자리가 줄어든다).

## 공식 문서 (2026-09-17 갱신본)

- Function calling: `toolChoice`는 `"auto"`, `"none"`, 또는 특정 함수 객체(`{"type":"function","function":{"name":…}}`). `required`/`any`는 문서에 없다. 모델별 제한은 적혀 있지 않고, 튜닝 모델은 지원하지 않는다. 추론(thinking)·이미지와 같이 쓸 수 없고, `maxTokens` ≥ 1024. https://api.ncloud-docs.com/docs/clovastudio-chatcompletionsv3-fc
- Structured Outputs: HCX-007만. `responseFormat: {type: "json", schema}`. `pattern` 미지원, `enum`·`anyOf`·`minItems` 등 일부만. 추론·Function calling과 같이 쓸 수 없다. https://api.ncloud-docs.com/docs/clovastudio-chatcompletionsv3-so
- 레포 기존 실측과 일치: HCX-005에 `response_format`을 보내면 400(`core/llm.py`, 2026-11-08). 기능 고르기는 이미 DASH-002 강제 호출로 돌고 있다(`feature_selector.py`).

## 실측 (HCX-005, temperature 0.2, 각 5회)

시스템 한 줄 + 대화 1~3턴, 도구는 그 기능 하나만. 스크립트는 로컬 scratch(커밋 안 함).

| 턴 (S1 원래 시나리오) | auto | 강제 | 인자 |
|---|---|---|---|
| 가격 답 "3500원이요" (`missing-menu-price`) | 5/5 호출 | 5/5 | 정확 (`피로시키, save, 3500`) |
| 앞 메뉴 저장 뒤 "라면도 5000원" (`two-menu-prices`) | 5/5 | 5/5 | 정확 |
| 미리보기 고침 "아 6500원으로" (`p3-upsert_menu-revise`) | 5/5 | 5/5 | 정확 |
| 두 요일 다른 시간 (`two-hours-while-pending`) | 5/5 | 5/5 | **10/10 틀림** (월요일 호출에 금 포함) |

한계: 실제 에이전트 문맥(긴 시스템 프롬프트, 기능 안내, 작업 원장, 이전 미리보기)을 넣지 않은 최소 재현이다. 이 차이가 실패의 원인이라는 것은 아직 추론이다.

## 설계 함의

- **모델의 일:** 이번 말 → (작업 act, 기능, 인자). 도구는 그 기능 하나만 붙이고 강제 호출한다. 앞 맥락은 대화 기록 대신 작업 원장의 **상태 요약**(기능, 받은 값, 단계)으로 준다.
- **코드의 일:** 필수 값 비었으면 되묻기, 미리보기, 승인, 저장, 완료 문구(상태에서 생성), 보류 작업 재개. 모델은 사장님에게 보이는 문장을 쓰지 않는다.
- **스키마:** 모델이 틀릴 수 있는 묶음을 없앤다(영업시간은 요일별 항목 배열 등).
- **대안(이게 안 되면):** LangGraph로 역할 하나짜리 노드를 잇는다. act 분류(DASH-002 강제) → 인자 추출(HCX-005 강제 또는 HCX-007 SO) → 규칙 노드(검증·되묻기·미리보기·승인). 위 구조를 그래프로 명시한 것과 같아서, 둘은 경쟁안이라기보다 같은 설계의 구현 방식 차이다.
