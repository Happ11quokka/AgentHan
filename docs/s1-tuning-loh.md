## 바꾼 것 (원인 → 수정, `owner_assistant.py`·`task_ledger.py`, tuning-points 단계)

1. **③④ 끝난 같은 기능 작업의 대화가 다음 변경을 막음** (`two-menu-prices`)
   - 첫 메뉴 변경(미리보기 → 네 → 저장)이 문맥에 있으면 두 번째 변경에서 모델이 "변경하시겠습니까?"로 글로 물었다.
     같은 문장으로 앞 대화가 있으면 6/6 실패, 없으면 3/3 성공.
   - 같은 기능의 끝난 작업 메시지는 모델 문맥에서 뺀다. 저장한 내용은 "앞서 끝난 작업" 줄에 남긴다(`저장함 {...}`).
     그 줄은 최근 5개 + 같은 기능의 끝난 작업 전부(`TaskLedger.log(feature, last=5)`).
   - 다른 기능의 끝난 작업까지 빼면 "11시부터 5시까지"를 15:00으로 읽는 일이 늘어서(기준선 코드 4/4 → 2/4) 같은 기능으로 한정했다.
2. **③ 새 작업의 조회 질문이 보류된 작업의 다음 답을 가져감** (`slot-switch-coupon`)
   - 쿠폰 입력 중 "오늘 들어온 주문 있어요?"에 비서가 "어떤 주문을 접수할까요?"로 끝내 주문 작업이 열린 채 남았다.
   - 그 말로 처음 열린 작업이고, 말이 질문이며 바꾸는 말이 없으면 답한 뒤 닫는다(`_only_asks`, DASH act와 무관).
3. **⑦ 도구 없이 쓴 확인·완료 문구와 글로 쓴 호출을 더 잡음** (`p3-upsert_menu-revise` 등)
   - 문장 안에 쓴 `upsert_menu(…)`도 실제 호출로 바꾼다(호출이 정확히 하나일 때만, 값 확인·미리보기·승인은 그대로).
   - `FAKE_ASK`·`FAKE_DONE`에 "추가하겠습니다·하도록 하겠습니다·~드리겠습니다·도구를 불러오는 중·성공했습니다" 등 추가.
     저장하지 않았는데 "성공했습니다"라고 답하던 것이 막힌다.
4. **⑦ 조회를 안 하고 되묻거나 지어냄** (`long-session-a`, `slot-switch-hours`, P1 조회)
   - 필수 입력이 없거나 사장님 말에 이미 있는 조회(전화 기록, "이번 주" 정산)는 답이 물음표로 끝나도 한 번 다시 요청한다.
   - 다시 요청해도 조회하지 않으면, 사장님 말이 질문이고 입력이 다 말에 있을 때 코드가 조회 도구를 실행하고 모델은 결과만 문장으로 쓴다
     (`code_read`, 인자는 말에서 읽은 선택값만: 이번 주 → this_week, 부재중 → missed_only).
   - POS 연동 확인은 첫 줄을 코드가 도구 결과로 쓴다("'하나로페이'은(는) 지금 네이버 플레이스와 연동되지 않아요.").
5. **④⑤ 미리보기 중 항목 추가** (`two-hours-while-pending`, 9번과 함께)
   - 항목을 더하는 턴은 시스템 프롬프트에 그렇다고 적고(`ADD_NOTE`) 앞 항목의 확인된 값을 비운다.
   - 한 호출에 여러 항목을 목록으로 넣으면(`closed: [true, false]`) `one_value_per_call` 오류로 항목마다 따로 부르게 한다.
6. **⑥ 대표키워드 전체 목록** (`p2-set_representative_keywords-ask_fill`, `slot-switch-new-task`)
   - "이렇게 세 개로", "A, B, C로요"인데 모델이 차이(add+remove)나 전체 목록+remove로 보내면 전체 목록(keywords)으로 바꾼다.
     따옴표 안 새 키워드("수제 메도빅")는 옛 키워드("메도빅")를 말한 것으로 보지 않고, "빼/삭제"가 있으면 바꾸지 않는다.
     목록의 단어는 모두 값 확인을 다시 거친다.
7. **⑥ 메뉴 값 변경에 붙은 확인 안 된 action** — 가격·이름·설명이 확인됐는데 action(예: on_sale)만 확인 안 되면 기본(save)으로.
8. **⑦ 미리보기 흉내** (3dfdf10) — "더미 답변 작성 (실제 전송 없음): {…}", "이렇게 바꾸면 될까요?"처럼 시스템 미리보기를
   흉내 낸 답도 도구 없는 확인으로 잡는다(`long-session-b` 톡톡 답장).
9. **④ 한 호출에 묶은 여러 요일** (177e809, `two-hours-while-pending`)
   - HCX-005가 "그리고 금요일은 …"에 월·금을 `days=[mon, fri], closed=[true, false], …`로 묶어 보낸다(5번 중 4번).
     오류를 돌려줘도 다시 부르지 않아서 코드가 요일마다 한 호출로 나눈다(`_unpack_items`, 쉬는 날은 시각을 뺀다).
   - 승인 대기 중인 같은 변경 비교는 인자 JSON을 풀어서 한다(공백만 다른 중복이 미리보기에 두 번 나오던 것).
   - 항목을 더하는 말(그리고 + 값)에 도구 없이 답하면 문구와 상관없이 한 번 다시 요청한다.
   - 영업시간 가이드에 쉬는 날 예시와 "요일마다 값이 다르면 따로, 목록으로 묶지 않는다"를 넣었다(합성 재생 m0 재생성).
10. **⑦ 지난 변경을 묻는 질문** (bbdb41b) — "아까 아메리카노 얼마로 바꿨죠?"에 "바꿨어요"가 지어낸 저장으로 잡혀 다시 요청하고,
    그 요청이 HCX에 거절돼 3/3 실패했다. 바꾸는 말 없는 질문이면 다시 요청·"아직 저장하지 않았어요" 바꾸기를 하지 않는다.

    바꾸는 말 없는 질문이고, 키워드가 정확히 한 기능(조회 전용)에만 있고, DASH가 고른 기능에는 키워드가 없으면 그 조회 기능으로 보낸다.

12. **⑦ 미리보기를 고치는 말** (1f96dc7, `p3-upsert_menu-revise`)
    - 미리보기 뒤 "가격은 5500원으로 바꿀게요"에 HCX-005가 6번 중 5번 도구 없이 "추가하겠습니다… 도구 실행 중",
      `{'name': …, 'price': 5500}`처럼 글로 답했다.
    - 보여 준 변경을 값과 함께 고치는 말에 도구 없이 답하면 문구와 상관없이 한 번 다시 요청한다(항목 추가와 같게).
    - 노출된 도구가 하나일 때 글로 쓴 인자 사전(`{...}`)도 그 도구 호출로 본다.
    - 그래도 안 부르면, 고친 미리보기의 숫자 인자가 하나이고 사장님 말의 새 숫자가 하나일 때 그 숫자만 바꾼 호출을
      코드가 만든다(`_number_edit`). 값 확인·새 미리보기·승인은 그대로. 디버그 6회: 4/6 → 6/6.

    - 앞 요청("월요일은 쉬는 걸로")이 문맥에 있으면 모델이 월요일을 다시 묻거나 "금요일은 이미 9시부터 밤 11시"라고 답했다.
    - 미리보기에 항목을 더하는 턴은 이번 말만 모델에 보낸다(보여 준 항목은 시스템이 들고 있고 `ADD_NOTE`가 알린다).
