## 바꾼 것

**도구 스펙** (`docs/tools.md`에 정리, 결정 A~D)
- 메뉴 `upsert_menu`: `action`(등록·삭제·품절·품절 해제), `new_name`, `description`. 별칭으로도 찾음. `owner_tools.py`를 없애고 17개 도구를 `feature_tools.py` 한 곳에 둠
- 업체 정보: `field`/`value` → 항목별 인자(name·address·phone·introduction, 여러 개 한 번에)
- 영업시간: `day` → `days` 목록(요일·날짜·평일·주말·매일), 브레이크 타임, 기간 휴무
- 대표키워드: `add`/`remove` + 전체 교체 `keywords`
- 주문·예약: 선택 `reason`. 정산 기간은 공통 기간 표현
- 카탈로그 설명을 실제 되는 일에 맞추고 임베딩 인덱스를 다시 만듦
- S1 원본(flow.jsonl) 인자 11건을 새 모양으로 옮기고 `scripts/build_s1.py`로 s1.jsonl 재생성

**채점 정답 수정**
- 도움말: 맞는 글이 없을 때 도구가 고객센터 글을 "찾은 것처럼" 돌려주던 것 → `found: false`. 정답도 "못 찾음/고객센터 안내"로
- POS 미지원: "어렵습니다", "연결할 수는 없지만" 같은 표현도 인정
- 통계: 정답이 저장소 통계(340회)였는데 앱은 R1 주간 리포트(1,260회)로 답함 → 리포트 값으로 맞춤

**앱 수정 (S1 실패에서 찾은 것)**
- 숫자 읽기 버그: "금액만 3000원" → 13000, "2만원" → {2, 10000}으로 읽던 것 수정 (쿠폰 수정값이 안 바뀌던 원인)
- 통계 답 첫 줄에 실제 조회 수 표시 (카드는 증감만 있어서 "몇 번 봤어요?"에 답이 없었음)
- 모델이 도구 없이 "변경하시겠습니까?/접수하겠습니다/맞나요?/create_coupon(...)"으로 답하면 한 번 다시 요청
- 조회 기능에서 도구 없이 지어낸 답(부재중 5통 등)이면 한 번 다시 요청
- HCX가 400으로 거절하면 같은 요청을 한 번 더
- 승인 대기 중 "메도빅 가격 얼마죠?"를 DASH가 none으로 보내던 것 → 가게 메뉴 이름 + 가격 말이면 메뉴로 (답한 뒤 승인 대기 작업이 다시 위로)
- 리뷰 답글 초안 대기 중 짧은 "등록해/올려줘"는 리뷰 흐름으로
- 사진 메뉴 초안 하나에 가격만 말했는데 모델이 고치지 않으면 코드가 가격을 넣음
- 사장님 말에 없는 사유(reason)·설명은 되묻지 않고 뺌
- "이 세 개로 해 주세요"가 `add`로 와서 5개를 넘으면 전체 교체로

## 남은 실패 / 아직 안 한 것

3회 모두 성공하지 못한 시나리오(최종): `two-menu-prices` 0/3, `slot-switch-coupon` 0/3,
`p2-create_coupon-ask_fill` 1/3, `p3-upsert_menu-revise` 1/3, `two-hours-while-pending` 1/3,
`missing-menu-price`·`p2-set_representative_keywords-ask_fill`·`decline-then-redo`·`long-session-a` 2/3.

- 대부분 같은 원인: 값이 다 모였는데 HCX-005가 도구를 부르지 않고 "변경하시겠습니까?", "추가하겠습니다. 도구 실행 중..."처럼
  글로 답한다. 한 번 다시 요청해도 또 그렇게 답하는 경우가 남는다. 변경 전보다 나빠진 4건
  (`p3-upsert_menu-revise` 3→1, `slot-switch-coupon` 2→0, `two-hours-while-pending` 3→1, `missing-menu-price` 3→2)도 이 유형이다.
  변경 전 실행과 같은 날 1회씩 잰 것이라 모델 흔들림과 이번 변경의 영향을 아직 나눠 보지 못했다.
- `slot-switch-coupon`: 쿠폰 입력 중 "오늘 들어온 주문 있어요?"에 모델이 "어떤 주문을 접수하실 건가요?"로 끝내 주문 작업이 열린 채 남고,
  다음 쿠폰 기간이 주문 쪽으로 간다.
- 최종 실행 뒤에 넣은 것(미측정): 글로 쓴 `create_coupon(...)`을 실제 호출로 바꾸기. 시각 목록 예외 수정은 남은 27개 시나리오에만 들어갔다.

- 쿠폰 최소 주문 금액·대상 메뉴는 넣었다 뺌: 선택 입력으로 열어 두면 모델이 매번 되물어 쿠폰 만들기가 끝나지 않았음
- 리뷰 도구 기간(1d~all)과 통계 `get_statistics`(7d·30d)는 공통 기간으로 안 바꿈
- `tests/fixtures/replay/live.json`(L2 실측 녹화)은 다시 녹화하지 않음. 관련 테스트는 원래 xfail
- 기준선 저장은 하지 않음 (이 커밋에서 `--save-baseline`으로 다시 재면 기준선이 된다)
