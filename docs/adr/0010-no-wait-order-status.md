# 0010. 통화 중 대기를 없애고 주문 현황으로 확정을 알린다

## 상태

Accepted (2026-11-21). [ADR-0009](0009-phone-order-store-approval.md)의 "혼합 대기(통화 중 20초 → 문자)"를 대체한다. 0009의 나머지(가게 승인 원칙, 5분 자동 취소, 화면이 꺼지면 자동 확정, 오늘 품절)는 그대로다.

## 맥락

0009대로 만들고 11/21 전화 시연을 해 보니 손님이 복창에 "네"라고 한 뒤 대기음을 들으며 최대 20초를 기다렸다. 사장님이 20초 안에 못 누르면 "확인되는 대로 문자로 확정 알려 드릴게요"로 끊고, 손님은 통화 화면의 "받은 문자" 미리보기로 결과를 봤다. 그 미리보기는 통화 화면이 열려 있는 동안(최대 6분)만 살아 있어서, 화면을 새로 고치거나 닫으면 주문이 어떻게 됐는지 다시 볼 길이 없었다.

0009는 "통화 뒤 문자로만 결정"을 버렸다. 손님이 늘 "문자 기다리세요"를 듣고, 화면 앞의 사장님이 바로 눌러도 통화 안에서 빼기·바꾸기·시각을 물을 수 없다는 이유였다. 시연에서 이 두 가지가 다르게 보였다.

- 20초는 들고 있기에 길었다. 대기음과 10초 재촉이 시연의 흐름을 끊었다.
- 손님은 배민처럼 "주문을 넣고 끊으면 가게가 확인해 알려 주는" 흐름에 익숙하다. 기다리라는 말을 오히려 낯설어한다.
- 문자 미리보기 대신 주문 번호로 언제든 다시 열 수 있는 주문 현황을 만들 수 있다. 결과를 놓칠 걱정이 줄어든다.

## 결정

통화 안에서는 사장님 결정을 기다리지 않는다. 결정은 통화 뒤에 주문 현황으로 알린다.

1. 복창 "네" → 엔진이 확인 요청을 통화 뒤 단계로 열고 "주문 넣어 드렸어요. 가게에서 확인하면 화면으로 알려 드릴게요. 감사합니다."라고 한 뒤 바로 끊는다. 대기 대사·대기음·10초 재안내는 없다. 확인 요청을 "접수"라고 부르지 않는다(용어집).
2. 사장님 카드는 처음부터 "통화 뒤 확인"(ru "Подтверждение после звонка")으로 뜨고 5분 카운트다운 하나만 보인다. 버튼은 0009와 같다([수락] [+15분] [+30분] [거절 → 재료 소진·바쁨·가게 사정·직접 쓰기]).
3. 통화 뒤 결정의 뜻: 수락 → 확정. 늦춘 수락 → 바뀐 시각으로 바로 확정(손님에게 되묻지 않는다). 거절 → 취소(재료 소진이면 고른 메뉴가 오늘 품절). 5분 무응답 → 자동 취소.
4. 통화가 확정 주문으로 끝나면 손님 화면이 주문 현황으로 바뀐다. 단계는 주문 넣음 → 가게 확인 중 → 확정(또는 취소) → 픽업 시각이고, 담은 메뉴·금액(쿠폰을 썼으면 할인 전 금액·쿠폰 이름·낼 금액)과 거절 사유·떨어진 메뉴를 보인다. 남은 5분은 손님에게 보이지 않는다.
5. 주문 번호(추측할 수 없는 통화 id)가 열쇠다. 주소 `/phone/orders/<주문 번호>`와 브라우저 저장소에 남아 새로 고치거나 나중에 열어도 보인다. 조회 `GET /api/phone/orders/{id}`, 실시간 갱신 `…/stream`(SSE, 끊기면 조회로 다시 읽음). 토큰은 없다. 조회는 사장님 허브의 카드를 먼저 보고, 없으면(서버가 다시 뜸) DB `phone_orders`의 마지막 상태를 읽는다.
6. 손님 취소를 새로 둔다(`POST /api/phone/orders/{id}/cancel`, 처리 상태 `customer_cancelled`). 가게 확인 중이거나 늦춘 수락으로 확정됐을 때만 된다. 제시간 수락·거절·자동 취소·이미 취소한 주문은 거부하고(409, 이유 코드), 제시간 수락 주문에는 "취소하려면 가게로 전화 주세요"만 보인다. 손님 취소와 사장님 결정은 "한 주문에 결정 한 번"을 같이 따른다. 늦게 온 쪽이 거부되고 진 쪽 화면은 이긴 결과를 보인다.
7. 사장님 화면이 꺼져 있거나 승인 설정이 꺼져 있으면 0009처럼 자동 확정이다. 이때는 주문이 정말 확정이라 예전 확정 마무리 대사(픽업 시각 포함)를 그대로 쓰고, 주문 현황은 곧바로 "확정"이다.
8. 핸드오프·손님이 통화 중에 취소한 통화·무응답으로 끊긴 통화는 주문 현황으로 가지 않고 통화 결과를 보인다.
9. 통화는 문자를 약속하지 않는다(PR #44 리뷰). 실제 문자는 나가지 않고 손님 화면의 "받은 문자"도 없어졌다. 그래서 마무리 대사에 붙던 "여쭤보신 건 확인해서 문자로 알려 드릴게요"를 뺐고, 사장님 질문 시간 초과는 "죄송해요, 사장님이 지금 바로 답하기 어려우세요.", 자유 입력 답은 "사장님이 글로 답을 남기셨어요. 자세한 건 가게에 물어봐 주세요.", 통화 중 대기를 켠 경로의 시간 초과는 "… 확인되면 화면으로 알려 드릴게요."다.
10. 주문 현황의 제목 밑 한 줄(`detail`)과 쿠폰 줄 이름(`amount.coupon_label`)은 서버가 손님 문자 문장(`sms.py`)·통화의 쿠폰 이름 말로 준다. 화면은 같은 문장을 다시 쓰지 않는다(PR #44 리뷰).
11. DB에서 다시 읽은 결정 전 주문은 요청을 연 시각 + 5분이 지났거나, 주문서 시각이 지금(가게 시계)보다 뒤면 자동 취소로 읽는다. 뒤의 경우는 `PHONE_NOW` 시계가 다시 뜬 서버에서 같은 시각부터 다시 가서 생긴다: 그 주문의 허브 타이머도 결정할 곳도 서버와 함께 사라졌다(PR #44 리뷰). 허브에 카드가 없어 스트림이 거절(404)되면 화면은 스트림을 다시 여는 5초마다 조회로 다시 읽어 스스로 바뀐다.

통화 중 대기는 지우지 않고 설정으로 남긴다: `PHONE_APPROVAL_WAIT_S`의 기본을 20에서 0으로 바꿨다. 0보다 크게 주면 0009의 통화 중 경로(대기음, 늦춘 시각 되묻기, 재료 소진 뒤 빼기·바꾸기)가 그대로 돈다. 기본 흐름과 시연은 0이다. `Order`·`OrderSink` 계약은 이 결정으로 바뀌지 않았다(같은 날 쿠폰 할인 칸과 낼 금액 속성 `Order.subtotal`·`Order.total`이 따로 더해졌다).

## 대안

- **0009 그대로(통화 중 20초 → 문자)**: 시연에서 20초가 길었고, 결과를 보는 문자 미리보기는 다시 열 수 없었다.
- **통화 중 대기를 줄인다(예: 5~10초)**: 사장님이 조리 중이면 대부분 넘겨서 결국 통화 뒤로 간다. 손님은 짧게라도 기다린 뒤 "나중에 알려 드릴게요"를 듣는다. 두 길을 다 유지하는 비용만 남는다.
- **문자 미리보기를 고쳐 쓴다**: 실제 문자는 보내지 않는다(범위 밖). 미리보기를 오래 붙잡아 두는 것보다 주문 번호로 다시 여는 화면이 실제 서비스(배민 주문 상세)와 닮았다.
- **주문 현황에서 손님이 주문을 고친다**: 사장님이 이미 만들기 시작했을 수 있고, 다시 확인 요청을 열어야 한다. 취소만 둔다.

## 결과

- 얻은 것: 손님 통화가 "네"에서 바로 끝난다. 결과를 주소 하나로 언제든 다시 본다(서버가 다시 떠도 DB에서). 사장님은 20초 압박 없이 5분 안에 누르면 된다. 늦춘 시각이 싫은 손님은 주문 현황에서 취소한다. 발표에서는 "주문을 넣고 끊으면 가게가 확인해 확정을 알려 준다(배민과 같은 흐름)"로 말한다.
- 잃은 것: 통화 안에서 주문을 살리는 길이 기본 흐름에서 빠졌다. 늦춘 시각을 통화 중에 되묻지 못하고(통화 뒤에는 새 시각으로 바로 확정하고 싫으면 손님이 취소), 재료 소진이면 그 메뉴를 빼거나 바꿔 주문을 살리지 못하고 주문 전체가 취소된다(손님은 [다시 주문하기]로 새로 건다). 손님 질문에 대한 사장님의 늦은 답도 통화가 끝난 손님에게는 더 보이지 않는다(사장님 카드의 문자 칸에만 남는다).
- 그대로인 것: 가게 승인 원칙, 요청을 연 때부터 5분 자동 취소, 화면이 꺼지면 자동 확정, 재료 소진 → 오늘 품절, 결정·사유의 DB 기록(손님 취소는 `owner_status` `customer_cancelled`로 더해졌다).
- 남겨 둔 것: 손님 문자 미리보기 SSE(`GET /api/phone/calls/{id}/sms`, `customer_texts_router`)는 손님 화면이 더 열지 않지만 지우지 않았다. 허브는 사장님 카드의 문자 칸에 같은 미리보기를 쌓고, 통화 중 대기를 켠 경로(`PHONE_APPROVAL_WAIT_S` > 0)와 시험이 이 스트림으로 문자를 본다. 실제 문자·알림톡 발송을 정할 때 같이 정리한다.
- 후속: 5분 자동 취소 값은 대기 0에 맞춰 리허설에서 다시 본다. 실제 문자·알림톡 발송, 통화 뒤 시각 재협상, 주문 현황에서 주문 고치기는 범위 밖이다.
