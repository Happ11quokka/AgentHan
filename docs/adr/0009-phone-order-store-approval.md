# 0009. 전화 주문은 가게 승인으로 성립한다 (혼합 대기: 통화 중 20초 → 문자, 5분 자동 취소, 화면 꺼지면 건너뜀)

## 상태

Accepted (2026-11-21)

## 맥락

손님이 복창에 "네"라고 하면 AI가 바로 "6시 반까지 준비해 둘게요"로 통화를 끝내고 확정 문자를 보냈다. 사장님 화면의 주문 카드는 "새 주문 → 접수"뿐이라 거절할 수 없었다. 11/21 멘토링(사근동) 지적: 재료가 떨어졌거나 시간을 못 맞출 수 있으니, 배민처럼 가게가 승인해야 주문이 성립해야 한다. 지금은 너무 일방적이다.

제약:

- 손님은 전화를 들고 있다. 오래 기다리게 할 수 없다.
- 사장님은 조리 중이라 카드를 바로 못 볼 수 있다.
- 심사위원은 배포 서버에 혼자 전화해 본다. 사장님 화면을 켜 둔 사람이 없을 수 있다.

## 결정

주문은 가게가 수락해야 성립한다. 기다림은 통화 중과 통화 뒤를 섞는다.

1. 복창 "네" → AI가 "사장님께 주문 확인 중이에요. 잠시만요."라고 하고 사장님 화면에 확인 요청 카드를 연다. [수락] [+15분] [+30분] [거절 → 사유: 재료 소진 / 바빠서 못 맞춤 / 영업·가게 사정 / 직접 쓰기].
2. 통화 중 대기는 카드를 보낸 때부터 20초다(10초쯤 재안내 한 번, 대기음). 그 안의 결정은 손님이 통화에서 바로 듣는다. 늦춘 수락은 바뀐 시각을 묻고 "네"면 확정, "아니요"면 취소다. 재료 소진은 그 메뉴를 빼거나 바꾸게 하고, 빼기만 하면 재승인 없이 확정한다.
3. 20초가 지나면 "확인되는 대로 문자로 확정 알려 드릴게요. 확정 문자를 받으시면 주문 완료예요."로 통화를 끝낸다. 주문서는 넘어가고 카드는 통화 뒤 대기로 남는다.
4. 요청을 연 때부터 5분 안에 결정이 없으면 자동 취소(`expired`)하고 손님에게 취소 문자를 남긴다.
5. 설정 `PHONE_OWNER_APPROVAL`이 꺼져 있거나 사장님 화면 연결(SSE 구독자)이 0이면 승인을 건너뛰고 예전처럼 바로 확정한다. 카드에 "자동 확정(사장님 화면 꺼짐)"을 남긴다.
6. 재료 소진으로 고른 메뉴는 오늘만 품절이 된다. 진행 중인 통화와 다음 통화에 적용되고, 날짜가 바뀌면 풀린다.

시간은 설정값이다: `PHONE_APPROVAL_WAIT_S`(20) · `PHONE_APPROVAL_REPROMPT_S`(10) · `PHONE_APPROVAL_EXPIRE_MIN`(5). `OrderSink`·`Order` 계약은 그대로 두고, 사장님 처리 상태(`new`·`accepted`·`rejected`·`expired`, 아래 추가 결정 3의 `cancelled`·`auto_accepted`)는 계약 밖(허브 카드·DB `phone_orders.owner_status`)에 둔다. 넘김(`handoff`) 주문은 승인 대상이 아니다.

## 추가 결정 (구현·리뷰 뒤, 2026-11-21)

1. **통화 중 결정은 통화가 말해야 굳는다.** 사장님이 통화 중에 누른 결정은 카드에는 바로 보이지만(두 번째 결정은 409), 손님 문자와 DB 기록은 통화가 그 결정을 손님에게 말하기 시작할 때(`approval_said`) 남긴다. 그 전에 손님이 주문을 고치거나 취소해 요청을 거두면 거둔 쪽이 이긴다: 카드는 "고치는 중"·손님 취소로 돌아가고 확정 문자·수락 기록은 없다. 세션은 아직 말하지 않은 20초 시간 초과보다 먼저 와 있는 사장님 결정을 말한다(재료 소진 메뉴가 든 주문을 시간 초과로 확정하지 않는다). 시간 초과 대사가 먼저 나갔거나 손님이 끊어 말하지 못한 결정은 통화 뒤 결정처럼 문자로 알린다. 까닭: 같은 순간 사장님 수락과 손님 취소가 겹치면 손님은 취소했는데 확정 문자와 수락 기록이 남았다(코드 리뷰).
2. **대기 중 "취소할게요"는 확인 질문 동안 "고치는 중"으로 보인다(spec과 다름).** spec은 대기 중 취소를 곧바로 취소로 닫는다고 했다. 구현은 평소 취소처럼 "주문 취소할까요?"를 먼저 묻고, 묻는 순간 요청을 changed로 거둔다(사장님 카드 "손님이 주문을 고치는 중", 버튼 없음). 손님이 "네"라고 하면 같은 번호를 cancelled로 다시 알려 카드가 "손님이 주문 취소"가 된다. "아니요"면 다시 복창하고 새 번호로 요청한다. 까닭: 묻는 사이 사장님이 수락하면 손님이 취소하려던 주문이 확정된다. 손님이 "아니요"라고 할 수도 있어 바로 취소로 닫지 않는다.
3. **처리 상태 어휘는 `expired` 말고도 둘이 더 있다.** 늦춘 시각을 손님이 거절하면 카드 처리 상태가 `cancelled`다(사장님 결정은 늦춘 수락으로 남고 주문만 취소). 승인을 건너뛴 자동 확정은 카드에서는 `accepted` + `auto_accepted` 표시지만 DB `owner_status`에는 `auto_accepted`로 남는다(사장님이 승인하지 않은 주문을 기록에서 가르려고). 팀 공지에는 `expired`·`cancelled`·`auto_accepted` 셋을 함께 알린다. 계약(`OrderSink`·`Order`)은 그대로다.
4. **손님 "받은 문자" 스트림 창.** 4단계의 2분(`TEXTS_WINDOW_S` 120초)은 최소값으로 두고, 서버가 `max(120초, 자동 취소 마감 + 60초)`로 연다(기본 6분). 창 길이는 `sms.snapshot`의 `window_s`로 화면에 알리고 화면도 그 창에 맞춰 닫는다(마감 설정을 늘려도 통화 뒤 결정 문자를 놓치지 않게).
5. **자동 취소가 통화 중 대기보다 짧으면 서버가 뜨지 않는다.** `PHONE_APPROVAL_EXPIRE_MIN`×60 ≤ `PHONE_APPROVAL_WAIT_S`이면 `SettingsError`다. 통화 중 카드가 손님이 기다리는 동안 자동 취소되는 모순이라, 조용히 고치지 않고 배포 때 바로 드러나게 한다.

## 대안

- **통화 중에만 기다림**: 사장님이 못 보면 손님이 계속 기다리거나 주문이 사라진다. 20초를 넘겨 붙잡아 둘 수 없다.
- **통화 뒤 문자로만 결정**: 손님이 늘 "문자 기다리세요"를 듣는다. 화면 앞의 사장님이 바로 눌러도 통화 안에서 대안(빼기·바꾸기·시각)을 물을 수 없다.
- **승인 없이 확정 + 사장님이 나중에 취소**: 지금 동작과 같다. 멘토 지적을 풀지 못한다.
- **화면이 꺼져도 승인 대기**: 사장님이 없는 시간의 주문(심사위원 전화 포함)이 모두 5분 뒤 취소된다.

## 결과

- 좋아지는 점: 만들 수 없는 주문을 가게가 막는다. 재료 소진이 다음 통화에 바로 반영된다. 시간을 늦춰 주문을 살릴 수 있다. 결정과 사유가 DB에 남는다.
- 감수할 점: 손님 통화가 최대 20초 길어진다. 통화 뒤로 넘어간 주문은 확정 문자를 받기 전까지 미정이다. 화면이 꺼진 가게는 원칙의 예외(자동 확정)다. 발표에서는 "화면을 켠 상태가 영업 중"으로 설명한다.
- 후속: 20초·10초·5분은 리허설에서 다시 맞춘다. 문자는 미리보기만(실제 발송 없음). 시각 재협상·부분 거절 버튼·품절을 비서 "내 가게" 메뉴와 맞추기는 범위 밖이다.
