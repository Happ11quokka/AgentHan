# 파이프라인에서 손댈 수 있는 곳 (2026-11-12)

사장님 한마디가 답이 될 때까지 거치는 단계마다 **바꿀 수 있는 것**, **지금 값**, **S1에서 어디로 드러나는지**를
적었다. 우선순위는 매기지 않았다. 무엇을 먼저 할지는 S1 기준선과 게이트(정본 §6) 결과를 보고 정한다.
수치는 [`docs/s1-2026-11-12.md`](s1-2026-11-12.md) 최종 실행 기준이다.

```
사장님 말 → ⓪ 상태 규칙 → ① 후보 5개 → ② 기능 선택(DASH) → ③ 작업 원장(act)
        → ④ 실행(HCX-005 + 그 기능 도구 하나) → ⑤ 값 확인 게이트 → ⑥ 복구 장치
        → ⑦ 미리보기·승인 → ⑧ 답 문장
   (위임: 리뷰 서브에이전트 · 메뉴/음식 사진 · 통계 리포트)
```

  - 해당 시나리오: `two-menu-prices` 0/3, `p2-create_coupon-ask_fill` 1/3, `p3-upsert_menu-revise` 1/3, `two-hours-while-pending` 1/3, `missing-menu-price` 2/3.

- 선택 입력(쿠폰 최소 주문 금액·대상 메뉴)을 열면 모델이 매번 되물었다. 그래서 도구 스펙을 넓힐 때마다 S1로 확인해야 한다.

모델이 틀린 모양으로 답할 때 코드가 고치는 장치들이다. 하나씩 패치로 붙었으므로 정리 대상이기도 하다.

| 장치 | 하는 일 |
|---|---|
| `FAKE_ASK`·`FAKE_DONE` + `NUDGE` | 도구 없이 "하시겠습니까/했습니다"로 답하면 한 번 다시 요청 |

| `_said_price`, `_keywords_as_list` | 사진 초안 가격 넣기, 키워드 add → 전체 교체 |

## 손대도 점수만 바뀌는 곳 (파이프라인 아님)

S1 채점 쪽(`scripts/build_s1.py`의 답 허용 표현 `NEGATIVE`·`HELP_NOT_FOUND`, 정답 사실)을 고치면 점수가 바뀌지만
비서가 나아진 것은 아니다. 채점이 틀렸을 때만 고치고, 고친 커밋은 파이프라인 변경과 나눠 데이터셋 버전이 바뀐 것으로 다룬다
(게이트는 `s1.jsonl` 버전이 다르면 미완료로 본다).
